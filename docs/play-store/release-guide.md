# 플레이스토어 출시 가이드

이 문서대로 플레이 콘솔에 입력하면 된다. 등록정보 문구는 `listing.md`, 이미지는 `graphics/`에 있다.

## 0. 출시 전에 할 것

1. **이 브랜치를 main에 합친다.** 개인정보처리방침 주소
   (`https://github.com/happyfamily1984/news-alert/blob/main/docs/privacy-policy.md`)가
   main에 있어야 열린다. 앱 설정 화면의 '개인정보처리방침'도 같은 주소를 연다.
2. **업로드 키를 깃허브 시크릿에 등록한다** (아래 3번). 등록하면 이후 버전은
   CI가 플레이용 AAB까지 자동으로 만든다.
3. **업로드 키 파일(`upload-keystore.p12`)과 비밀번호를 안전한 곳 두 군데 이상에 보관한다.**
   저장소에는 없다. 잃어버리면 플레이 콘솔에서 업로드 키 재설정을 요청해야 한다.

## 1. 앱 만들기

플레이 콘솔 → 앱 만들기

| 항목 | 입력 |
|---|---|
| 앱 이름 | 뉴스 알리미 - 키워드 뉴스 알림 |
| 기본 언어 | 한국어 – ko-KR |
| 앱 또는 게임 | 앱 |
| 무료 또는 유료 | 무료 |

## 2. 앱 콘텐츠 (정책 → 앱 콘텐츠)

### 개인정보처리방침
`https://github.com/happyfamily1984/news-alert/blob/main/docs/privacy-policy.md`

### 광고
광고 없음

### 앱 액세스 권한
모든 기능을 특별한 액세스 권한 없이 사용할 수 있음 (로그인 없음)

### 콘텐츠 등급 (IARC 설문)
- 카테고리: **참고 자료, 뉴스 또는 교육**
- 폭력·성적 콘텐츠·욕설·약물·도박: 모두 **아니요**
  - 단, 설문에 "뉴스 등 실제 사건을 다루는 콘텐츠" 문항이 나오면 **예** (뉴스 기사 제목에
    사건·사고가 나올 수 있음)
- 사용자 간 소통·콘텐츠 공유: **아니요** (공유 버튼은 기사 링크를 다른 앱으로 넘기는 것뿐)
- 위치 공유: 아니요 / 디지털 상품 구매: 아니요

### 타겟층 및 콘텐츠
- 대상 연령: **18세 이상** 만 선택 (13세 미만이 포함되면 가족 정책 심사가 추가된다)
- 아동에게 호소력 있는 앱인가: 아니요

### 뉴스 앱
- "뉴스 앱입니까?" → **예**
- 뉴스 앱 정책 요건: 기사마다 출처(언론사)와 발행 시각을 표시하고, 원문 링크를 제공한다.
  앱 설명과 처리방침에 개발자 연락처(플레이 개발자 이메일)가 있다.

### 데이터 보안
| 질문 | 답 |
|---|---|
| 필수 사용자 데이터 유형을 수집하거나 공유합니까? | **아니요** |
| (위가 아니요면 나머지 항목은 자동으로 건너뜀) | |

근거: 키워드·기사 기록·설정은 기기 안에만 저장되고 외부로 전송되지 않는다.
RSS 요청에는 개인정보나 키워드가 담기지 않는다. 광고·분석·오류 수집 SDK가 없다.

### 정부 앱 / 금융 기능 / 건강 앱
모두 해당 없음

## 3. 업로드 키를 깃허브 시크릿에 등록

깃허브 저장소 → Settings → Secrets and variables → Actions → New repository secret

| 이름 | 값 |
|---|---|
| `UPLOAD_KEYSTORE_BASE64` | `upload-keystore.base64.txt` 파일 내용 전체 |
| `UPLOAD_STORE_PASSWORD` | `key.properties`의 storePassword |
| `UPLOAD_KEY_ALIAS` | `upload` |
| `UPLOAD_KEY_PASSWORD` | `key.properties`의 keyPassword |

등록 후 Actions → Build APK → Run workflow 를 돌리면 Artifacts에
`news-alarm-play-aab`(플레이 업로드용)과 `news-alarm-release-apk`(직접 설치용)가 생긴다.

## 4. 앱 번들 올리기

조직 계정이라 비공개 테스트(테스터 12명·14일) 조건이 없다. 바로 프로덕션에 올린다.

1. 테스트 및 출시 → **프로덕션** → 새 버전 만들기
2. 플레이 앱 서명: **Google에서 생성한 앱 서명 키 사용**(기본값) 그대로 둔다.
   우리가 올리는 키는 '업로드 키'다.
3. `app-release.aab` 업로드, 출시 노트 입력 → 검토를 위해 전송

## 5. 직접 설치한 앱과의 관계

플레이 버전은 구글의 앱 서명 키로, 직접 설치용 APK는 공개 테스트 키로 서명된다.
서명이 달라서 **직접 설치한 앱 위에 플레이 버전을 덮어 설치할 수 없다.**
플레이에서 받기 전에 기존 앱을 삭제해야 한다 (키워드는 다시 등록해야 함).

## 6. 다음 버전 올릴 때

1. `pubspec.yaml`의 `version` 뒤 숫자(+16 → +17)를 반드시 올린다. 같은 번호는 플레이가 거부한다.
2. Actions에서 빌드 → `news-alarm-play-aab` 다운로드 → 플레이 콘솔에 업로드.

## 7. 알아둘 위험 요소

- **구글 뉴스 RSS 약관**: 구글 뉴스 RSS는 "개인 피드 리더에서 개인적·비상업적 용도로만"
  쓰도록 되어 있다. 이 앱은 무료·무광고이고 각 사용자의 기기가 직접 받아 보는 방식이라
  피드 리더와 같은 구조지만, 유료화나 광고를 붙이면 문제가 될 수 있다.
  중앙일보·YTN·MBC·KBS가 이 경로를 쓴다.
- **언론사 RSS 이용 조건**: 제목·요약만 보여주고 원문은 언론사 페이지로 연결한다.
  언론사가 이의를 제기하면 해당 출처를 빼야 한다.
- **배터리 최적화**: 플레이 정책상 '배터리 최적화 예외'를 앱이 직접 요청하지 않고,
  앱 정보 화면을 열어 사용자가 '제한 없음'을 고르게 안내한다.
